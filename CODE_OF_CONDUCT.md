# Code of Conduct
## Our Commitment
The BandTwine project is committed to providing a welcoming, inclusive, and harassment-free environment for all contributors, regardless of age, body size, disability, ethnicity, gender identity and expression, level of experience, nationality, personal appearance, race, religion, or sexual identity and orientation.

## Standards
Contributors are expected to:

- **Be Respectful**: Treat all community members with respect and consideration
- **Be Collaborative**: Work together constructively and help others learn
- **Be Professional**: Focus on technical merit and project goals
- **Be Accountable**: Take responsibility for mistakes and learn from them
- **Be Inclusive**: Welcome newcomers and diverse perspectives

### Unacceptable Behavior
The following behaviors are not tolerated:

- Harassment, intimidation, or discrimination in any form
- Offensive comments related to personal characteristics
- Unwelcome sexual attention or advances
- Trolling, insulting comments, or personal attacks
- Publishing others' private information without permission
- Other conduct that would reasonably be considered inappropriate

### Code Quality Expectations
All contributors must adhere to our technical standards:

1. **Correctness First**: Code must compile and pass all tests before submission
2. **Performance Awareness**: Consider resource constraints (memory, battery, boot time)
3. **Simplicity Over Complexity**: Prefer straightforward solutions to clever abstractions
4. **Documentation**: Comment on WHY, not WHAT; refactor unclear code first
5. **Testing**: Include tests for new features and bug fixes

### Review Process
Code reviews focus on:

- Technical correctness and performance
- Adherence to style guidelines (tabs, formatting, comments)
- Completeness of testing
- Clarity of implementation

Feedback should be:
- **Constructive**: Point out issues with suggestions for improvement
- **Specific**: Reference exact code locations and standards violated
- **Educational**: Explain the reasoning behind requested changes
- **Respectful**: Critique code, not people

## Scope
This Code of Conduct applies to:

- Project repositories and pull requests
- Issue trackers and discussions
- Community forums and chat channels
- Project events and meetups
- Public spaces when representing the project

## Enforcement
### Reporting
If you experience or witness unacceptable behavior:

1. **Document**: Note what happened, when, and who was involved
2. **Report**: Contact project maintainers at [@ZhianTeam](https://github.com/orgs/ZhianTeam/people)
3. **Confidentiality**: Reports will be kept confidential

### Response
Maintainers will:

1. **Acknowledge** reports within 144 hours
2. **Investigate** by gathering context from all parties
3. **Decide** on appropriate action based on severity
4. **Communicate** the outcome to relevant parties

### Consequences
Depending on severity, violations may result in:

- **Warning**: Private clarification of expectations
- **Temporary Suspension**: Time-limited ban from project spaces
- **Permanent Ban**: Indefinite exclusion from the project
- **Public Statement**: In cases affecting project reputation

### Appeals
Decisions may be appealed by:

1. Contacting a different maintainer within 14 days
2. Providing new information or context
3. Explaining why the decision was inappropriate

## Technical Philosophy
Beyond interpersonal conduct, we value:

### Code as Communication
Code is written once but read many times. We prioritize:
- Clarity over cleverness
- Directness over indirection
- Simplicity over flexibility

### Resource Stewardship
BandTwine targets embedded devices with limited resources:
- Every kilobyte of heap matters
- Every millisecond of boot time matters
- Every percent of battery matters

Contributors should respect these constraints and understand that performance optimization is not premature—it's mandatory.

### Intellectual Honesty
We value:
- Admitting when you don't know something
- Asking questions before making assumptions
- Testing hypotheses rather than guessing
- Learning from mistakes openly

### Surgical Precision
Changes should be:
- **Focused**: Address only the stated problem
- **Justified**: Every modified line traceable to the task
- **Verified**: Tested on target hardware when possible
- **Documented**: With commit messages explaining context

## Continuous Improvement
This Code of Conduct evolves with our community:

- Propose changes via pull request
- Discuss ambiguities in issues
- Share feedback on what works and what doesn't

Our goal is a healthy, productive community that builds exceptional software for wearable devices.
