### <ruby>結<rt>ゆ</rt>彩<rt>あ</rt></ruby> Next

*Xiaomi Smart Band / Watch で Twine を遊び尽くそう。しかし、その体験はこれまでのものを遥かに凌駕しています。*

---

**BandTwine** *(結彩)* は、革命的なインタラクティブ・フィクション（ノベルゲーム）エンジンである [Twine](https://twinery.org/) をサードパーティが移植・実装したプロジェクトです。

私たちは、Twine が持つ強力かつ自由度の高いストーリーテリング能力を、HyperOS (NuttX) 搭載の Xiaomi スマートウェアラブルデバイスへと移植しました。これらのデバイスは、[AstroBox](https://github.com/AstralSightStudios/AstroBox-NG) から「手首の上の蒸気機関」（笑）と揶揄されるほど極めて限られたリソースしかありませんが、それを実現したのです。

## Twee 互換性
`{}` や `[]`、そして延々と続く `$(...)` のデバッグに疲れていませんか？ Gentoo Linux の USE フラグを設定するかのように、変数定義の下準備に追われる日々にもううんざり？ 私たちは、Twine 公式のマークアップ言語である **Twee** をフルサポートしました。
多くの GUI エディタから Twee ファイルを出力できます。まずは、こちらの**クイック比較**をご覧ください：

```json
// BandTwine オリジナル版のナラティブロジック（公式サンプルより）
// 冗長で S/N 比が著しく低く、エントロピーも極めて高い。開発者や作者に甚大な認知負荷を強いる。

{
  "metadata": {
    "indexNode": "start"
  },
  "variables": {
    "player": {
      "hasKey": false
    }
  },
  "nodes": {
    "start": {
      "text": "静かな部屋で目が覚めた。カーテンの隙間から差し込む光が床を照らしている。部屋の向こう側には、固く閉ざされた木製のドアがある。どうする？ {0}、{1}、それとも {2}？",
      "links": [
        { "text": "窓の外を見る", "target": "look_outside" },
        { "text": "ベッド脇の机を調べる", "target": "check_desk" },
        { "text": "ドアの方へ歩く", "target": "locked_door" }
      ]
    },
    "look_outside": {
      "text": "カーテンを開けると、外には静かな森が広がり、木々の間に薄霧が立ち込めていた。\n\n{0}",
      "links": [
        { "text": "部屋の中央に戻る", "target": "start" }
      ]
    },
    "check_desk": {
      "text": "机に近づくと、そこには消えたランプと、閉じられた古い本が置かれていた。どうする？ {0}、それとも {1}。",
      "links": [
        {
          "text": "本を手に取る",
          "target": "found_key",
          "actions": [
            { "type": "set", "target": "var.player.hasKey", "value": true }
          ]
        },
        { "text": "放っておく", "target": "start" }
      ]
    },
    "found_key": {
      "text": "本を持ち上げると、その下から小さな真鍮の鍵が見つかった。あなたはそれをポケットに入れた。\n\n{0}",
      "links": [
        { "text": "部屋の中央に戻る", "target": "start" }
      ]
    },
    "locked_door": {
      "text": "頑丈な木製のドアだ。古い真鍮の鍵穴がついている。\n\n{0}\n{1}\n\n鍵の状態：{var.player.hasKey}",
      "links": [
        {
          "text": "鍵を使ってドアを開ける",
          "target": "door_unlocked",
          "condition": "var.player.hasKey"
        },
        { "text": "引き返す", "target": "start" }
      ]
    },
    "door_unlocked": {
      "text": "鍵を鍵穴に差し込んで軽く回すと、カチリと音がしてドアが開いた。扉の向こうは自由へと続く廊下だ。あなたの冒険は、まだ始まったばかりだ……"

  }

```

では、Twee ならどう書けるでしょうか？
> [!IMPORTANT]
> **互換性に関する注意**
>
> BandTwine Next は現在、**SugarCube** ストーリーフォーマットのみをサポートしています。**書き出す前に、必ず「デフォルトストーリーフォーマット」を確認してください！**
> 
> もしあなたが Twine のベテランで、他のストーリーフォーマット（Chapbook など）のサポートも希望される場合は、**Issue を立てるか、BandBBS コミュニティのコメント欄**で教えてください！

```twee
:: 開始
<<tag "start">>
<<set $gotKey to false>>
静かな部屋で目が覚めた。カーテンの隙間から差し込む光が床を照らしている。部屋の向こう側には、固く閉ざされた木製のドアがある。
どうする？ [[窓の外を見る|窓の外]]か、[[ベッド脇の机を調べる|机を調べる]]か、それとも[[ドアの方へ歩く|ドアに行く]]か？

:: 窓の外
カーテンを開けると、外には静かな森が広がり、木々の間に薄霧が立ち込めていた。
[[部屋の中央に戻る|開始]]

:: 机を調べる
<<script 'prompt.showToast({ message: `鍵の所持状態：$gotKey`, duration: 1500 })'>>
机に近づくと、そこには消えたランプと、閉じられた古い本が置かれていた。どうする？ [[本を手に取る|本を手に取る]][$gotKey to true]か、それとも[[放っておく|開始]]か？

:: ドアに行く
<<script 'prompt.showToast({ message: `鍵の所持状態：$gotKey`, duration: 1500 })'>>
頑丈な木製のドアだ。古い真鍮の鍵穴がついている。

<<if $gotKey === true>>
先ほど見つけた鍵のことを思い出した。[[鍵を使ってドアを開ける|ドアを開ける]]か、[[引き返す|開始]]して探索を続けることができる。
<<else>>
ドアは固く閉ざされている。鍵も持っていない。仕方なく[[引き返す|開始]]することにした。
<</if>>

:: 本を手に取る
<<script 'prompt.showToast({ message: `鍵を見つけた！現在の所持状態：$gotKey`, duration: 1500 })'>>
本を持ち上げると、その下から小さな真鍮の鍵が見つかった。
[[部屋の中央に戻る|開始]]

:: ドアを開ける
鍵を鍵穴に差し込んで軽く回すと、カチリと音がしてドアが開いた。扉の向こうは自由へと続く廊下だ。あなたの冒険は、まだ始まったばかりだ……
```

シンプルで直感的。見たままが得られる。JavaScript の埋め込みに対応し、Vela API の呼び出しもサポートしています。

Twee 初心者のために、豊富なドキュメントと、参考になる [インタラクティブ・チュートリアル](https://huanmeng692.github.io/Tutorial/) を用意しました。[^1]

[^1]: この素晴らしいチュートリアルを作成してくれた [@huanmeng692](https://github.com/huanmeng692/) に心から感謝します！

## 主な特長
- [x] **Twine Twee に完全対応。** 「Vim の抜け方が分からない」とか「なぜかまた JSON の構文エラーが出た」なんて頭を悩ませる必要はもうありません！お好みの Twine エディターを使って Twee 形式でエクスポートするだけで、手軽にプロジェクトへ統合できます。[NeG Converter](/conv/QUICKSTART.md) と組み合わせれば、旧バージョンの BandTwine JSON からのシームレスな移行も可能です。
- [x] **エレガントな KDL 設定。** 煩わしい `metadata` 属性ブロックや、目眩のするような `{{{{[{[{}]}]}}}}` のネストとはもうおさらば！KDL 設定は人間に極めて優しく、`/-` によるノード単位のコメントアウトに対応しているだけでなく、構造化されたマルチパラメーターノード設計を採用。さらにバイナリ TLV フォーマットへ直接コンパイル可能なため、実行時オーバーヘッドは完全にゼロです。
- [x] **「蒸気機関」向けに極限まで最適化。** 軽量＆スピーディーでありながら強力。Twee 内への JavaScript 直接埋め込みに対応し、各種 Vela API も自由自在に呼び出せます。
- [x] **コードを減らして、開発をもっと楽しく。** たった 1 つの BandTwine プロジェクトで、Xiaomi や REDMI の各種スマートバンド・スマートウォッチ端末上でのクロスプラットフォーム動作を実現します。
- [x] **100% 伝統と信頼の「人間による手作業コーディング」。** お忘れなく、私自身も一人の [Vela 開発者](https://github.com/fywmjj/better-mb9p-ATRI) なのですから。

## 対応デバイス
> [!IMPORTANT]
> Vela かんたんアプリ（QuickApp）が動作するのは、中国本土向けに販売された Xiaomi のスマートバンドやスマートウォッチのみのようです。互換性については、ご自身でお試しくださいね。

| ブランド | タイプ | モデル | サポート状況 | 備考 |
|-------|------|-------|--------|------|
| Xiaomi | スマートバンド | 10 シリーズ | ✓ 完全対応 | リアル「蒸気機関」上でテスト済み。 |
| | | 9 Pro | ✓ 完全対応 | リアル「蒸気機関」上でテスト済み。 |
| | | 9（通常版 / NFC） | 🟡 一部対応 | リアル「蒸気機関」上でテスト済み。一時的な回避策が必要 [^2]。修正を試みています。 |
| | | 8 Pro | ✓ 完全対応 | |
| | スマートウォッチ | S5 / 4 / 3 | ✓ 完全対応* | 実機が手元にないため、より多くのテストフィードバックが必要です。 |
| REDMI | スマートウォッチ | 5 / 4 | ⚪ 対応中 | 「Xiaomi スマートウォッチ」と同様。 |
| | スマートバンド | すべて | × 非対応 | 非 Vela デバイス。 |

[^2]: `manifest.json` 内の `designWidth` を `212` に変更する必要があります。
